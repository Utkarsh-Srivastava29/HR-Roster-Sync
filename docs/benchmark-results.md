# Benchmark results

Generated by `com.moveinsync.roster.bench.Benchmark` (`scripts/benchmark.sh`). In-memory store, so the numbers are our code, not a database.

**Machine:** Intel(R) Xeon(R) Processor @ 2.10GHz, 2 vCPU, JVM max heap 512 MB, OpenJDK 64-Bit Server VM 21.0.12.1, Linux amd64

## 1. Live HR feed (`POST /api/v1/hr/events` path, without HTTP)

200,000 creates in 200 batches of 1,000, 8 client threads.

| metric | value |
|---|---|
| throughput | 37,943 records/s |
| per record (validate + lock + decide + commit + outbox) p50 / p99 | 23 / 6375 us |
| per 1,000-record batch p50 / p99 | 180 / 729 ms |
| replay of the same 200,000 records | 200,000 duplicates, 0 new change events, 1.8 s |

## 2. Outbox relay

Drained a backlog of 200,000 change events in 0.35 s (573,762 events/s) to an in-process bus with the booking consumer.

## 3. Nightly reconciliation of a 200,000-row export

| scenario | diff time | total incl. apply | buckets opened / 4,096 | max rows in memory | result |
|---|---|---|---|---|---|
| identical file | 2138 ms | 2172 ms | 0 | 0 | COMPLETED {} |
| file cut off at 120,000 of 200,000 rows (no trailer) | 2420 ms | 2435 ms | 4096 | 5,100 | **BRAKED** - appears to be missing 80,000 records; nothing applied |
| 1% changed, 0.5% new, 1% missing | 2776 ms | 2870 ms | 3001 | 5,194 | COMPLETED {deactivate.APPLIED=2000, upsert.APPLIED=3000} |

"Max rows in memory" is the largest number of rows the diff held at once (file rows + store rows of the buckets being compared in one partition). The 200,000-row file itself is only ever streamed.

The whole benchmark - including the in-memory store of 201,000 employees and 205,000 outbox events in the same heap - runs with `-Xmx512m`.
